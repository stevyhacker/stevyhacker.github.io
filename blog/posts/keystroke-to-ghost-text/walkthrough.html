How it works today

Eleven steps, one local model, about 140 ms

Every suggestion takes this path. Most of the work is deciding when to stay quiet and keeping the ghost honest. The model call itself is about 60 ms of it.

  1. Keystroke

    The keyboard tap sees the key before the app has updated the field.

    event tap

  2. Wait for the app

    Reads the field over Accessibility until the app publishes the new text and caret.

    10 ms, then every 15 ms · max 400 ms

  3. Type-through

    If you typed exactly what the ghost showed, the ghost just advances. No model call.

    0 model calls

  4. Gates

    Stops at secure fields, excluded apps and sites, search fields, a selection, text after the caret, a likely typo, or Escape's quiet period.

    Escape = 10 s quiet

  5. Debounce

    Waits briefly. The wait is sized from how fast the last generation was.

    20 · 25 · 55 ms tiers

  6. Prompt

    Text before the caret, after a short preface: app, window title, field label. Optional: visible text, saved meeting facts, accepted phrases.

    ≤ 2,500 chars · 500 words

  7. Local model

    Gemma 4 E2B Base (Q6) runs in-process on the GPU through llama.cpp. If it fails, an HTTP llama-server covers for 60 s.

    ≈ 55–60 ms warm

  8. Heal and decode

    Cuts the prompt back to the word boundary and makes decoding re-type it, so half-typed words get completed. Stops near four words or a sentence end.

    ≈ 6 tokens

  9. Clean-up

    Drops echoes of typed text or hidden context, repeats of text after the caret, placeholders and unsafe output. Checks the seam.

    suppress, don't guess

  10. Ghost

    Drawn on the field's own baseline in its own font. The next word to accept is drawn stronger.

    ≈ 140 ms median, key to visible

  11. Accept and top up

    Tab takes one word, the backtick takes the rest. With two words left, a top-up asks for three more and stops at the sentence end.

    top-up at ≤ 2 words

Proposal

Local first. The cloud only fills gaps it can hide in.

A cloud call takes 212 ms at the median and 417 ms at p95, about three and a half times the local model. Nobody should wait for it. Two moments already have slack: a top-up, where words are still on screen, and a pause, where nothing is being typed.

When each result lands

Time after the trigger. Model and request time only; Accessibility reads and drawing add the same to both.

local modelcloud, median with p95 whiskerwaiting for quiet

Ask the cloud when

  • A top-up startsTwo words are left on screen, so a 212 ms answer arrives before the ghost runs out whenever those words take more than about 0.2 s to accept.
  • The user pausesAbout 350 ms with no key, a ghost showing and nothing accepted yet.
  • The context is long or not EnglishLong-context checkpoints scored 38% vs 28%, multilingual 62.5% vs 57.5%. Small samples, so route these only after shadow data agrees.
  • Local stayed quiet but the user is pausedFill the silence instead of replacing anything.

Stay local when

  • Every keystrokeThe first ghost always comes from the Mac. Nothing waits on the network.
  • The caret is mid-wordLocal completes fragments at 72%. The cloud adds nothing there and costs a call.
  • The field or app is privateSecure fields, excluded apps and domains, and anything the user has not opted in.
  • The cloud is failing or offlineThree failures in a minute pause the cloud for 60 s, like the local engine's retry cooldown.

How to build it

Two new parts, two hooks, one setting

Most of the machinery exists. The benchmark already runs the cloud route through the production prompt builder and clean-up.

New · lane

CotypingCloudLane

  • One request in flight, cancelled by the next keystroke.
  • 450 ms budget; three failures in a minute pause it for 60 s.
  • Chat request, thinking off (reasoning_effort: "none"), straight to Cerebras; OpenRouter adds about 23 ms.
  • Answers cached by suggestion anchor, so typing through a ghost reuses them.
New · pure

CotypingHybridMerge

The merge table above as one function of local text, cloud text, accepted words and idle time. Unit-tested the same way as CotypingSuggestionExtension.

Hooks · coordinator

CotypingCoordinator

  • extendSuggestionIfNeeded() starts local and cloud top-ups together; the first one that passes the seam check and arrives before the ghost runs out wins.
  • A pause timer starts in showOverlay and is cancelled by any input.
Move · from the benchmark

ChatContinuationEngine

Moves from the replay harness into the app: the app's autocomplete instruction as the system message, the rendered prompt as the user message. Key stored in the Keychain.

Setting · privacy

Cloud boost, off by default

  • Reuses CotypingAvailability for secure fields and excluded apps and sites.
  • Sends the draft and app, title and field label. Screen text and meeting facts need a second switch.
  • Says plainly that typed text leaves the Mac.
Measure

CotypingStats counters

Cloud calls, answers in time, first-word agreement, swaps, and accepted words by source. The same counters drive the rollout gates below.

Rollout

Prove it on real typing before it touches the screen

The benchmark is synthetic English scored by exact match. Real acceptance is the number that matters, and shadow mode measures it without risk.

  1. Shadow mode

    Call the cloud at top-ups and pauses but never show the answer. Log whether the next words you typed matched local or cloud, and whether the cloud answered in time.

    go on if cloud first word beats local by ≥ 3 points and ≥ 90% of top-ups land in time

  2. Cloud top-ups

    The cloud fills top-ups only. Nothing already on screen changes, so the risk is lowest.

    go on if accepted words per suggestion rise and errors stay under 2%

  3. Pause upgrades that agree

    After a pause, the cloud only extends a ghost whose first word it agrees with.

    go on if extended ghosts are accepted further than local ones

  4. Swaps and routing

    Allow swaps on disagreement, and prefer the cloud for long context and non-English text, if shadow data backs both.

    stop if p95 passes 500 ms, swaps get dismissed, or acceptance falls to local's level
Limits

Cost, privacy and failure

Cost

About $0.10 per 1,000 cloud calls at benchmark-sized prompts (about 90 tokens). With screen or meeting context, up to about 800 tokens, closer to $0.80. If the cloud fires for one in four of 2,000 daily suggestions, that is roughly $0.05 to $0.40 a day. Estimates from OpenRouter's listed Cerebras price.

Privacy

LokalBot is local-first, so this has to be an explicit opt-in. Cerebras is listed on OpenRouter as not training on or keeping prompts; the direct API's terms still need a read. Pay-as-you-go allows 300 requests a minute for Qwen; the free trial's 5 a minute is unusable.

Failure

Nothing waits on the network. Offline, slow or failing, the lane drops its answer and the local ghost carries on exactly as today.

Open questions

What the numbers do not settle yet

  • The chat instruction is untuned. It returned nothing on 12% of checkpoints; a better instruction may close some of that.
  • Nemotron, DeepSeek and GLM were only tested as raw continuation. Through chat they might gain the way Qwen did.
  • How fast people actually Tab is unmeasured, so the top-up head start is an assumption until shadow mode reports it.
  • The app's own HTTP fallback sends unhealed prompts; the same weights scored 14% that way against 37% healed.
  • Scoring is exact first-word match on synthetic text. It penalises valid alternative wording and is not acceptance.
